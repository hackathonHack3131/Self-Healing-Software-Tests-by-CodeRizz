The Problem vs. The SelfHeal Solution

Why modern engineering teams waste hours fixing brittle test suites, and how intent-aware testing eliminates maintenance toil.

FRAGILE EXECUTION

Single-Page Script Breaks

// Traditional Playwright/Cypress script await page.click('#checkout-btn'); await page.fill('#card-input', cardNum); // Error: Element not found or hidden on Step 1 of wizard!
  • Rigid Linear Path: Hardcoded to single-page flow; fails immediately when checkout splits into 4 sub-pages.
  • Pipeline Stoppage: Blocked build requiring manual script rewrites across cart, shipping, payment, and review steps.
  • High Engineering Toil: Developers spend hours updating locators rather than building business features.
AUTONOMOUS RECONSTRUCTION

Intent-Driven Multi-Step Adaptation

// SelfHeal Intent Architecture AOM UI Drift Detected -> Deep Agent plans 10 validated steps Clean replay executes in fresh browser -> Invariants pass Recipe v2 automatically saved to MongoDB
  • Immutable Intent Contract: Test targets the verified goal ("Complete checkout with valid card") without rigid page assumptions.
  • Multi-Step Reconstruction: Deep Agent navigates wizard pages, fills required fields, and validates accessible names.
  • Deterministic Replay: Clean replay verifies order confirmation and math invariants from scratch. The AI never declares pass/fail.

ENGINEERING INTEGRITY

Core System Principles & Guardrails

Built with strict constraints to ensure automated testing is safe, predictable, and enterprise-ready.

Test Integrity Rule 1

Immutable Intent

The goal and invariants are cryptographically hashed. The agent can never modify test criteria or expectations to force a pass.

What It Protects
Prevents goal drift. The AI cannot weaken assertions, alter test data dictionaries, or change expected totals when a test encounters difficulty.
Why It Matters
Eliminates the dangerous failure mode where healing agents "pass" tests by deleting failing verification steps.
Enforced In Repository
intents/checkout_intent.json engine/recipes.py (load_intent, compute_intent_hash) AGENTS.md (Global Rule 1)
Verification & Outcomes Rule 5

Deterministic Verifier

AI models propose actions, but only deterministic code decides pass or fail during a from-scratch replay in a fresh browser session.

What It Protects
Protects against LLM hallucinations and confirmation bias. The agent has no tool or API that can declare a test pass.
Why It Matters
Strict mathematical and invariant checks (HTTP 200, confirmation order ID, total == $36.50) are evaluated purely in deterministic code.
Enforced In Repository
engine/verifier.py (verify_outcome) engine/orchestrator.py (_verify_and_finalize) AGENTS.md (Global Rule 5)
Agent Safety & Security Rule 3

No Generated Scripts

No LLM-generated Python, JavaScript, shell, eval, or exec. The model proposes strictly typed semantic actions validated before execution.

What It Protects
Completely mitigates Remote Code Execution (RCE) and Prompt Injection attacks from untrusted third-party web content.
Why It Matters
Allowed actions are limited to: goto_start, fill_field, and click_button. Every proposed action is schema-validated.
Enforced In Repository
engine/validator.py (validate_step_proposal) engine/actions.py (resolve_target) AGENTS.md (Global Rule 3 & 4)
Audit & Persistence Rule 17

Local MongoDB Persistence

Every execution, UI diff, triage diagnosis, and versioned recipe (v1 → v2) is logged with complete cryptographic lineage.

What It Protects
Guarantees full auditability and reproducible history. No recipe can be promoted without recorded run verification.
Why It Matters
Enterprise engineering teams can inspect timeline traces, exact AOM differences, and triage evidence for every healed test.
Enforced In Repository
webapp/db.py (MongoDBManager) engine/recipes.py (save_recipe version increments) MongoDB Collections: runs, recipes, contacts
Agent Safety & Security Rule 9 & 19

Origin Allowlist Guard

Strict network routing ensures the browser automation visits only registered, allowlisted target endpoints (:5000).

What It Protects
Strict SSRF guard. Blocks navigation to cloud metadata endpoints (169.254.169.254), private ranges, and non-allowlisted domains.
Why It Matters
Guarantees that autonomous browser sessions cannot be weaponized or redirected to internal networks or external third parties.
Enforced In Repository
engine/browser.py (BrowserSession route guard) engine/config.py (ALLOWED_ORIGINS) AGENTS.md (Global Rule 9 & 19)
Test Integrity Rule 4 & 10

AOM Accessibility Snapshots

Structural comparisons rely on accessible names, roles, and headings. Sensitive passwords and credit card inputs are never stored.

What It Protects
Zero secret leakage. The agent operates on semantic Accessible Object Models (AOM) rather than raw DOM dumps with sensitive user data.
Why It Matters
Reduces token overhead by 85% compared to raw HTML while ensuring card numbers and passwords never enter model contexts or baseline files.
Enforced In Repository
engine/snapshot.py (build_aom_snapshot) engine/diff.py (compute_aom_diff) AGENTS.md (Global Rule 4 & 10)
